# brunosouzas: project context

## Purpose

GitHub profile repository: its README is the page shown on github.com/brunosouzas. It has three parts, all in the brand of brunosouzas.com: the header (the site's home banner), the latest articles as a list (cover thumbnail beside the title, date and description, as the site lists them), and the "Find me" buttons. Anything else lives on the site.

Stack: Markdown, SVG, Python 3 (standard library only, `unittest`), GitHub Actions
Delivery: A live
Integration branch: `main`
Trivial: none
Deliver and verify: GitHub shows `main` on the profile at once; verify that the `checks.yml` run on `main` is green and https://github.com/brunosouzas shows the change

## Technology declarations

No dependency manifest: the scripts use only the Python standard library. The workflows run `python3` from the `ubuntu-latest` runner; locally any Python 3.10+ works.

## Layout and operation sources

- [README.md](README.md): the profile page. The block between `<!-- articles:start -->` and `<!-- articles:end -->` is generated; do not edit it by hand.
- `assets/site/`: copies of files from `public/images/home/` in the brunosouzas.com repository (banner, avatar, social icons). Refresh them by copying again when the site artwork changes; never edit them here.
- `assets/*.svg`: the header and the buttons, generated by `python3 scripts/build_assets.py` from `assets/site/`. Change the script, not the output.
- `assets/articles/`: one rounded cover thumbnail per latest article, generated by `python3 scripts/update_articles.py` from `https://brunosouzas.com/rss.xml`, which also writes the list in the README. The script needs each feed item's cover as `media:content` (added to the site by brunosouzas.com change `rss-item-cover`), downloads it, refuses covers that would not render through `<img>`, and removes the thumbnails of articles that left the list.
- `tests/`: `python3 -m unittest discover -s tests`.
- `.github/workflows/checks.yml`: on pull requests and on `main`, runs the tests and fails when `assets/` is not what the script builds.
- `.github/workflows/latest-articles.yml`: refreshes the list and thumbnails and commits to `main` only when they changed. It runs when the site is published (both site pipelines, in brunosouzas.com and brain, send a `repository_dispatch` of type `site-published` after the Cloudflare deploy, with the secret `GITHUB_PROFILE_DISPATCH_TOKEN` from the Azure variable group `vg-00-site-cloudflare`: a fine-grained token for this repository only, Contents read and write, valid one year), daily at 06:17 UTC as a safety net, and on demand from `main`. When the token expires the publish step only warns; renew it and update the variable.

The repository holds only what the README uses or what builds and checks it; remove a file when nothing uses it any more.

GitHub images in the README go through `<img>`: every SVG must be self-contained (no external references, no CSS, no scripts, fixed colours). Light and dark variants are switched with `<picture>` and `prefers-color-scheme`.

GitHub default branch inspected on 2026-10-06: `main`. Release bases are defined by the project sources, separately from that setting. Build/publish commands mentioned by those sources are context, not authorization.
