# brunosouzas: project context

## Purpose

GitHub profile repository: its README is the page shown on github.com/brunosouzas. It has three parts, all in the brand of brunosouzas.com (the v2 identity of the design system `@brunosouzas/design-system`): the header (the site's home banner), the latest articles as a list (cover thumbnail beside the title, date and description, as the site lists them), and "Find me", a row of icon-only links (brunosouzas.com, LinkedIn, Email). Anything else lives on the site.

Stack: Markdown, SVG, Python 3 (standard library only, `unittest`), GitHub Actions
Delivery: A live
Integration branch: `main`
Trivial: none
Deliver and verify: GitHub shows `main` on the profile at once; verify that the `checks.yml` run on `main` is green and https://github.com/brunosouzas shows the change

## Technology declarations

No dependency manifest: the scripts use only the Python standard library. The workflows run `python3` from the `ubuntu-latest` runner; locally any Python 3.10+ works.

## Layout and operation sources

- [README.md](README.md): the profile page. The block between `<!-- articles:start -->` and `<!-- articles:end -->` is generated; do not edit it by hand.
- `assets/site/`: `og-en.svg`, a copy of `assets-src/og/og-en.svg` in the brunosouzas.com repository, the source of the site's share image (`/og.image.png`). Refresh it by copying again, byte for byte, when the share image changes; never edit it here.
- `assets/design-system/`: the "Find me" icons, `link-<icon>.svg` and `link-<icon>-dark.svg` for `brunosouzas` (the site's b symbol, never the `website` globe), `linkedin` and `email`: the design system's link icons (`linkIcon`, 46x46, light and dark surface) as `@brunosouzas/design-system@0.12.0`'s cover command writes them, the same icons as stackledger's home links. They are rendered outside this repository and copied here byte for byte; never edit them here. To refresh them (a new pinned version), run this in an empty folder outside the repository, then copy `out/*.svg` into `assets/design-system/`:

  ```sh
  set -eu
  mkdir -p out  # the cover command does not create folders
  DS=@brunosouzas/design-system@0.12.0
  for row in "brunosouzas|brunosouzas.com|brunosouzas.com icon: the brand symbol, a b with a moon." "linkedin|LinkedIn|LinkedIn icon." "email|Email|Email icon."; do
    icon=${row%%|*}; rest=${row#*|}; title=${rest%%|*}; desc=${rest#*|}
    for surface in light dark; do
      suffix=; [ "$surface" = dark ] && suffix=-dark
      printf '{"id":"link-%s%s","format":"icon","title":"%s","description":"%s","pieces":[{"piece":"linkIcon","icon":"%s","surface":"%s"}]}\n' \
        "$icon" "$suffix" "$title" "$desc" "$icon" "$surface" > "link-$icon$suffix.json"
      npx --yes --package "$DS" brunosouzas-cover "link-$icon$suffix.json" --out "out/link-$icon$suffix.svg"
    done
  done
  ```

  In the README each icon is the whole link: `<a href=…><picture>` with the `-dark` file as the `prefers-color-scheme: dark` source and the light file in an `<img height="44">` whose `alt` is the link's accessible name (`brunosouzas.com`, `LinkedIn`, `Email`); no words, no `title`. The anchors sit on separate lines, so GitHub puts one space between them; with the room the icon keeps around its face, that is the small gap of stackledger's row.
- `assets/*.svg`: the header and the All articles button, generated by `python3 scripts/build_assets.py` from `assets/site/`. Change the script, not the output.
  - The header is the site's share image (`og-en.svg`, 1200x630), unchanged: the slogan "Code that runs for the problem you have." in Source Serif 4, the symbol, the four category badges and the signature. The slogan is text in a face embedded in the image (the `@font-face` exception below); the README's alt text carries the name and the slogan.
  - The All articles button follows the site's `.btn-primary` with the design system's colours (`brand.<theme>` tokens: white words on ink `#121212`, in dark `#121110` on `#F1EEE8`, and an arrow in the accent `#E04E17`/`#FF7A45`) and `radius.pill`. Its words are outlines (paths) in Source Sans 3 Bold, drawn by `scripts/glyphs.py` from `fonts/SourceSans3-Bold.ttf`: an SVG shown through `<img>` cannot load a web font, and these files carry no CSS.
- `fonts/`: `SourceSans3-Bold.ttf` and its `OFL.txt`, unmodified copies of the design system's `fonts/` (0.9.1). Refresh by copying; never edit.
- `assets/articles/`: one rounded cover thumbnail per latest article, generated by `python3 scripts/update_articles.py` from `https://brunosouzas.com/rss.xml`, which also writes the list in the README. The script needs each feed item's cover as `media:content` (added to the site by brunosouzas.com change `rss-item-cover`), downloads it, refuses covers that would not render through `<img>`, and removes the thumbnails of articles that left the list.
- `tests/`: `python3 -m unittest discover -s tests`.
- `.github/workflows/checks.yml`: on pull requests and on `main`, runs the tests and fails when `assets/` is not what the script builds. The tests also check that the README's Find me row is exactly the three icon-only links and that every file in `assets/design-system/` and `assets/site/` is used.
- `.github/workflows/latest-articles.yml`: refreshes the list and thumbnails and commits to `main` only when they changed. It runs when the site is published (both site pipelines, in brunosouzas.com and brain, send a `repository_dispatch` of type `site-published` after the Cloudflare deploy, with the secret `GITHUB_PROFILE_DISPATCH_TOKEN` from the Azure variable group `vg-40-app-brunosouzas-com-prod`: a fine-grained token for this repository only, Contents read and write, valid one year), daily at 06:17 UTC as a safety net, and on demand from `main`. When the token expires the publish step only warns; renew it and update the variable.

The repository holds only what the README uses or what builds and checks it; remove a file when nothing uses it any more.

GitHub images in the README go through `<img>`: every SVG must be self-contained (no external references, no scripts, fixed colours, no CSS). One exception, checked by `problems()` in `scripts/build_assets.py`: a `<style>` that holds only `@font-face` rules whose every `url()` is a `data:font/` URL. The site's v2 covers carry their face that way (the design system's ADR 0008, "Type inside the image"), and an embedded font renders through `<img>`; without the exception `update_articles.py` would refuse every v2 cover. The button this repository draws and the design system's link icons carry no CSS; the header keeps the share image's embedded face. Light and dark variants are switched with `<picture>` and `prefers-color-scheme`.

GitHub default branch inspected on 2026-10-06: `main`. Release bases are defined by the project sources, separately from that setting. Build/publish commands mentioned by those sources are context, not authorization.
